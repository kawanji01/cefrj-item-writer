# 対話フロー仕様（interaction-flow）

| 項目 | 内容 |
|---|---|
| 目的 | 作問エージェントと教師（作問者）との日本語対話を状態機械として固定し、質問文テンプレート・入力検証・照合対話・提案提示形式・進捗表示・教師照会・完了報告を、実装者が追加判断なしで実装できる粒度で定義する。 |
| 対象読者 | 実装担当（Codex GPT-5.6 sol）、コア指示書（`agent/author-core.md`）の執筆・保守者 |
| 参照文書 | `docs/requirements.md`（ユースケース・v2スコープ外リストの正）、`docs/architecture.md`（CLI契約・エラーコード目録の正）、`docs/question-generation-spec.md`（生成規則の正）、`docs/cefrj-validation-spec.md`（レベル体系・照合規則・機械検査の正）、`docs/subagent-review-spec.md`（再生成ループ・監査配置の正）、`docs/json-output-spec.md`（set.json・ID規則の正） |
| 規範語彙凡例 | 「しなければならない(MUST)」「してはならない(MUST NOT)」「すべきである(SHOULD)」「してもよい(MAY)」 |
| この文書が正とする範囲 | 対話状態機械（状態一覧・遷移条件）、各状態の日本語質問文テンプレート、入力検証と再質問文言、明示指定照合の対話フロー、提案フローの提示形式、進捗表示、不成立時の教師照会、完了報告様式。生成規則・検証規則・CLIの引数/終了コード・JSON構造はこの文書の正ではなく、上記参照文書に従う。 |

本文書の規則には `IF-xx`（挙動規則）、`QT-xx`（質問文テンプレート）、`RQ-xx`（再質問文言）、`DLG-xx`（対話フロー・文例）、`FMT-xx`(提示・報告様式) のIDを振る。他文書からは `docs/interaction-flow.md の IF-03` の形式で参照すること。

## 1. 全体フローと状態一覧

- **IF-01** 対話は完全に日本語で行わなければならない。対象語・形式コード・ID・ファイルパス(英語表記)は例外として英字のまま表記する。
- **IF-02** エージェントは1ターンに1つの質問だけを教師に提示しなければならない。1つの質問への回答が複数の値（対象語のリスト）を含むことは許可する。
- **IF-03** 対話は以下の状態機械に従わなければならない。状態の追加・削除・順序変更をしてはならない。

## 2. グローバル規則

- **IF-07** 教師の入力は解釈前に次の正規化を行わなければならない: 前後空白の除去、全角数字→半角数字、全角カンマ(、，)→半角カンマ、連続空白の1個化。対象語そのもの（英単語・複数語見出し）の内部は改変してはならない。
- **IF-08** グローバルコマンド「中止」: S10〜S70およびS81で教師が「中止」とだけ入力した場合、エージェントは「セットを中止します。ここまでの入力は保存されません。よろしいですか？（はい / いいえ）」と確認し、「はい」でS99へ遷移しなければならない。「いいえ」は直前の状態に戻る。
- **IF-09** グローバルコマンド「戻る」: S20〜S70で教師が「戻る」とだけ入力した場合、遷移表の直前の質問状態に戻り、その状態の確定値を破棄して再質問しなければならない。S10に「戻る」先はない（RQ-10を提示して留まる）。
- **IF-10** S80の実行中は教師入力を受け付けない。実行の中断はホストツール（Claude Code / Codex）の中断操作に委ね、本仕様のスコープ外とする。中断されたセットは `set.json` が書き込まれず監査のみ残る（`docs/architecture.md` の原子的完成規則）。
- **IF-11** 不正入力時は同一状態に留まり、状態ごとに定義された再質問文言（RQ-xx）を提示しなければならない。再質問回数の上限は設けない。
- **IF-12** 対話文中でレベル・品詞・カテゴリの実値を表示する場合、必ず `lookup.py` の照合結果（正規化データ由来）を用いなければならない。エージェント自身の言語知識でレベルを推定して表示してはならない。

## 3. 各状態の質問テンプレートと入力検証

質問文テンプレート中の `{...}` は実行時に置換するプレースホルダである。テンプレートの文面はそのまま使わなければならない（MUST）。

### 3.1 S10 形式選択

**QT-10**
```
問題形式を選んでください（番号または形式コードで回答してください）。

【語彙問題（CEFR-J Wordlist 準拠）】
 1. vocab_mcq_en2ja        英単語 → 日本語の意味 4択
 2. vocab_mcq_ja2en        日本語の意味 → 英単語 4択
 3. vocab_flashcard_en2ja  例文フラッシュカード 英 → 日
 4. vocab_flashcard_ja2en  例文フラッシュカード 日 → 英

【文法問題（CEFR-J Grammar Profile 準拠）】
 5. grammar_mcq                空欄4択の選択問題
 6. grammar_cloze              空欄自由入力の穴埋め
 7. grammar_reorder            語句整序
 8. grammar_rewrite            書き換え
 9. grammar_example_selfcheck  例文問題（訳を想起して自己採点・詳しい解説付き）
```

- 入力検証: 半角整数1〜9、または形式コード9値（`vocab_mcq_en2ja` / `vocab_mcq_ja2en` / `vocab_flashcard_en2ja` / `vocab_flashcard_ja2en` / `grammar_mcq` / `grammar_cloze` / `grammar_reorder` / `grammar_rewrite` / `grammar_example_selfcheck`）との完全一致のみ受理する。

**RQ-10**
```
入力を解釈できませんでした。1〜9 の番号、または一覧の形式コードをそのまま入力してください。
```

### 3.2 S20 レベル選択

**QT-20a**（形式が語彙4形式の場合）
```

```

**QT-20b**（形式が文法5形式の場合）
```
問題のCEFR-Jレベルを指定してください（9段階）:
```

- **IF-13** 確定したレベルは、語彙形式なら `level_scale` = `cefr`、文法形式なら `cefrj` として記録しなければならない。

```

```
（`{レベル例}` は語彙なら `A2`、文法なら `A2.1` とする）

### 3.4 S31 明示対象入力

**QT-31a**（語彙4形式）
```
対象の英単語を入力してください（{target_count_guidance}。複数の場合はカンマまたは改行で区切ってください）。
品詞まで指定する場合は「watch:verb」の形式で書いてください。
品詞表記は Wordlist の15種です: noun / adjective / verb / adverb / pronoun / preposition /
determiner / conjunction / number / modal auxiliary / be-verb / do-verb / have-verb /
interjection / infinitive-to
「CD player」のような複数語見出しもそのまま入力できます。
```

**QT-31b**（文法5形式）
```
対象の文法項目を入力してください（{target_count_guidance}。複数の場合はカンマまたは改行で区切ってください）。
次のいずれの書き方でも指定できます。
 - 教員版のID（例: 13、1-1）
 - 文法項目名またはその一部（例: 受動態、to不定詞）
対象にできるのは教員版でCEFR-Jレベルが付与された256項目のみです。
```

- `{target_count_guidance}` は初回入力では `1〜{set_question_max}件`、S40からの追加では `追加できる新規対象は1〜{remaining_capacity}件（既存対象の再入力は重複として除外します）` と展開する。`remaining_capacity = set_question_max - 現在の確定対象数` である。
- 入力検証: 初回入力は区切り後の件数が1〜`set_question_max`件であること。追加入力は既存集合を変更せず一時集合としてS32まで照合し、代替・取り下げ解決後に対象IDで既存集合と重複除去した新規対象数が0〜`remaining_capacity`件であること。新規対象数が残り容量を超えた場合は追加操作全体を不受理として元の集合を保持し、S31でRQ-31を提示する。新規対象数が0件なら追加なしを通知し、重複による場合は重複除去も通知して、元の集合のままS40へ戻る。語彙の `:pos` 指定は上記15種との完全一致だけを受理し、不一致の品詞表記はその項目のみ不正としてRQ-31で再入力を求める。
- **IF-14** 1対象は1問に対応する（1対象=1問）。同一の対象を同一セット内で重複指定された場合、エージェントは重複を除去し、その旨をS32の照合結果表示で通知しなければならない。
- **IF-14a** 明示モードの重複除去済み確定対象集合は、初回確定時、追加適用時、削除適用時、およびS40で「はい」を受理する直前に総件数が1〜`set_question_max`件でなければならない。追加は全候補の照合と重複除去が完了し、この不変条件を満たす場合だけ一括適用する。削除指定が全確定対象を含む場合は削除を一件も適用せず、元の集合を保持する。

**RQ-31**
```
入力を解釈できませんでした。{理由: 件数が0件です / 件数が上限{set_question_max}件を超えています /
追加後の新規対象数{new_target_count}件が残り容量{remaining_capacity}件を超えています /
品詞表記「{pos}」は15種の一覧にありません}。もう一度入力してください。
```
（`{理由:...}` は該当する1つだけを表示する）

### 3.7 S40 問題数確定

## 4. 明示指定照合フロー

### 4.1 照合手順

- **IF-17** S32では、S31で入力された対象を入力順に1件ずつ `lookup.py` で照合しなければならない（CLI契約の正は `docs/architecture.md`）。語彙は headword（+pos指定があればpos）と指定レベルL、文法はIDまたは項目名文字列と指定レベルLを渡す。
- **IF-18** 照合クリアの条件は `docs/cefrj-validation-spec.md` のターゲット適格規則に従う。要旨: 語彙=指定レベルLのシートに headword+pos が完全一致。文法=教員版256項目に含まれ、単一値はL一致、範囲値はLが[下限,上限]に包含。
- **IF-19** 照合結果は1件ごとに **FMT-32** の形式で表示しなければならない。全件の照合が終わるまでS40へ遷移してはならない。
- **IF-20** 照合NGは次の4類型に分類し、対応する対話（DLG-41/42/43/44）を行わなければならない。
  1. **レベル不一致**: 収録はあるが指定レベルLに適格な候補が0件。
  2. **辞書外**: 語彙=Wordlistに headword が存在しない。文法=教員版256項目に該当がない（ITEM LISTのみに存在する項目・レベル未付与16項目を含む）。
  3. **多品詞曖昧**: 語彙のみ。pos未指定で、指定レベルLに一致する品詞が2件以上ある。
  4. **形式不適合**: 形式が `grammar_reorder` または `grammar_rewrite` で、対象項目（pos/枝番の解決後の当該項目。親指定で全枝番が該当する場合を含む）の文タイプが先行文脈を要求する2値（`前文が肯定平叙` / `前文が否定平叙`。正は `docs/question-generation-spec.md` GEN-06/GEN-12）である。
- **IF-21** pos未指定で指定レベルLに一致する品詞がちょうど1件の場合は、その品詞を自動採用し、FMT-32の照合OK行に採用品詞を明示する（追加の質問はしない）。
- **IF-21a** 文法項目名またはその一部による入力は、`lookup.py gp --keyword` の指定レベルLに適格な結果が1件ならその項目を自動採用する。2件以上なら、形式適合性の判定前に **DLG-45** で全件を `lookup.py` の返却順のまま番号付き提示し、教師が選んだ1件だけを後続の形式適合性判定へ渡さなければならない。先頭候補その他を自動採用してはならない。候補提示と選択はS32内で行い、新しい状態を追加してはならない。
- **IF-22** DLG-41の選択肢「レベルを変更する」が選ばれた場合はS20に戻り、新レベル確定後に**確定済みを含む全対象**を再照合しなければならない。

**FMT-32 照合結果の表示形式**（1件1行〜1ブロック。この書式を変えてはならない）
```
照合OK : {入力文字列} → {entry_id または gp:ID}（{headword/文法項目(平易版)}, {pos（語彙のみ）}, {レベル値}）
照合NG（レベル不一致）: {入力文字列} — 収録レベル: {品詞とレベル、またはCEFR-Jレベル値の列挙}
照合NG（辞書外）      : {入力文字列} — {不在の説明}
照合NG（多品詞曖昧）  : {入力文字列} — 指定レベル {L} に {k} 品詞が一致
照合NG（形式不適合）  : {入力文字列} — 文タイプ「{文タイプ値}」は先行文脈を必要とするため {形式コード} では出題できません
```

> 以下の対話文例中のレベル値・品詞は例示である。実対話では `lookup.py` の照合結果の実値を表示しなければならない（IF-12）。

## 5. 提案フロー

### 5.1 候補の取得と提示

- **IF-30** S35では `lookup.py` を提案モードで実行し（CLI契約の正は `docs/architecture.md`）、指定レベルLにターゲット適格な候補一覧を取得しなければならない。語彙はS33の絞り込み条件（品詞・カテゴリ）を渡す。文法の候補母集団は教員版256項目のうちLに適格な項目のみとする。形式が `grammar_reorder` または `grammar_rewrite` の場合、先行文脈を要求する文タイプ（IF-20の類型4の2値）の項目を候補母集団から除外しなければならない（`lookup.py gp` の `--exclude-context-required` フラグを指定する。CLI契約の正は `docs/architecture.md` CLI-30）。

```
カンマ区切りで、除外だけ指定する場合は「除外: 3,5」の形式で回答してください。
```

### 5.2 選定の入力検証

- 入力検証: 「はい」（先頭N件を採用）、番号N個のカンマ区切り（表示済み番号の集合内・重複なし・ちょうどN個）、「除外: {番号列}」（除外後の残余の先頭N件を採用。残余がN件未満になる除外は不正入力）のみ受理する。

- **IF-33** 採用されなかった提示候補と未提示の適格候補は、提示順のまま補充プールとして記録しなければならない（補充の実行規則は `docs/subagent-review-spec.md`）。

### 5.3 DLG-35 候補不足の照会

```
 2. 絞り込み条件を変更する（語彙のみ。絞り込み条件入力に戻ります）
```
