## 独立検査の新規指摘

## R10-01 — major — `scripts/build_normalized.py:2464-2495`, `scripts/build_normalized.py:2681-2695`

1. **指摘内容**: 通常ビルドの出力先前提検査は、出力ディレクトリ直下に一時プローブを作れることだけを確認し、3つの最終パスを置換可能かは最初の書込み前に確認しない。現行metaを持つ一時出力先で、`lexicon.json`を旧内容の通常ファイル、`grammar.json`をディレクトリにして通常ビルドすると、プローブはpassし、`lexicon.json`の置換後に`grammar.json`の`os.replace()`が`IsADirectoryError`となった。CLIは定義済み`E-ENV-05`・終了コード1を返したが、出力先には新lexicon・ディレクトリのgrammar・旧metaという部分更新セットが残った。

2. **影響**: R9-03対応は直列化失敗を最初の置換前へ移したが、予測可能な最終パス不正や2件目以降のI/O失敗では正規化セットが混在状態になる。原本版またはパイプライン版を更新するビルドなら、異なる`data_version`の成果物が同居する。doctorは後から不整合を検出できるものの、通常ビルド自身が出力先書込み前提を処理開始前に満たさず、失敗時に既存の正規化セットを保存できない。

3. **根拠となる設計文書の規則ID**: `CLI-08`、`CLI-12`、`E-ENV-05`、`NRM-30`、`ERR-03`、`PLN-08`。

4. **具体的な修正案**: 最初の置換前に3つの最終パスを全件検査し、ディレクトリなど置換不能な対象が1件でもあれば`E-ENV-05`で停止する。さらに3つの一時ファイルをすべて作成・flush・fsyncしてから確定段へ進み、確定段の途中失敗でも旧セットへ戻せる協調置換または明示的ロールバックを実装する。少なくともlexicon・grammar・metaの各位置を通常ファイル以外にした3条件と、2件目・3件目の置換失敗を回帰検査する。

## R10-02 — major — `scripts/doctor.py:154-176`, `scripts/doctor.py:322-351`

1. **指摘内容**: D04は各スキーマをJSONとしてパースできるかだけを確認するため、トップレベル配列`[]`をpass扱いする。D11は直後に無条件で`schema.get("$schema")`を呼ぶが、`AttributeError`を捕捉しない。`candidate.schema.json`だけを`[]`にした一時環境でdoctorを実行すると、D11でスタックトレースが漏れ、終了コード2、stdout 0バイトとなった。12項目レポートも`E-ENV-04`の診断failも出力されなかった。

2. **影響**: JSON構文自体は有効だがJSON Schema文書ではないという、D11が診断すべき入力でdoctor自身が中断する。CLI-11の「failがあっても全12項目を最後まで実行」とERR-03の定義済みエラー変換を満たさず、環境修復に必要な一括診断を失う。

3. **根拠となる設計文書の規則ID**: `CLI-10`、`CLI-11`、`E-ENV-04`、`ERR-03`、`PLN-08`。

4. **具体的な修正案**: D11でトップレベルがobjectかを`.get()`前に検査し、非objectを対象ファイル付きの問題として収集する。併せて診断関数から漏れ得る型例外をD11のfailへ変換し、`[]`、`null`、文字列、数値の各スキーマ文書で12項目レポート・終了コード1・stderr空になることを回帰検査する。

## R10-03 — major — `scripts/build_normalized.py:240-248`, `scripts/build_normalized.py:281-299`, `scripts/build_normalized.py:2316-2327`, `scripts/doctor.py:265-280`

1. **指摘内容**: `strict_json_loads()`は`parse_constant`で`NaN`等を拒否するが、標準JSONの数値トークン`1e400` / `-1e400`は通常の`parse_float`経路に入り、CPythonのfloatでは正負の無限大になる。grammarの`efl.rel_freq.A1`を`1e400`にした一時環境では、jsonschemaがこの`inf`をnumberとして受理し、D09はpass、doctorは12 pass / 0 fail・終了コード0となった。一方、同じ値を`canonical_json_text(..., allow_nan=False)`へ渡すと`ValueError: Out of range float values are not JSON compliant`になる。

2. **影響**: doctorは本システムの正準JSON直列化器が扱えない正規化データを完全正常と認定する。後続CLIが当該数値を含むentryをstdoutまたは成果物へ転記すると、CLI-04の正準形を生成できず内部エラーになり得る。R9-02で閉じた非標準定数リテラルとは入力トークンが異なるため、現在の回帰条件を通過する。

3. **根拠となる設計文書の規則ID**: `CLI-04`、`CLI-10`、`CLI-11`、`NRM-03`、`NRM-30`、`E-DATA-04`、`ERR-03`、`PLN-08`。

4. **具体的な修正案**: 共通JSONローダーの`parse_float`で変換後に`math.isfinite()`を要求するか、ロード直後に全数値を再帰走査して非有限floatを拒否する。`1e400`と`-1e400`をnormalized・meta・sources・configへ投入し、それぞれの対象コードでdoctorが12項目を完走すること、および正準直列化不能な値をpassさせないことを確認する。

## R10-04 — minor — `scripts/build_normalized.py:2337-2391`

1. **指摘内容**: `validate_normalized_set()`はスキーマ・meta問題または現在値不一致が1件でもあると、3ファイルの相互`data_version`検査より前に`raise_normalized_data_failure()`を呼ぶ。lexiconだけをスキーマ適合する旧`data_version`へ変更し、grammar・metaを現行値のままにした一時環境では、D09は正しく`E-DATA-04`で停止したが、messageは`lexicon.data_version 期待... 実測...`だけで、「3ファイルのdata_versionが不一致」という内部矛盾を含まなかった。現在値不一致がない場合だけ後段の相互検査へ到達するため、R4-02で要求・解決記録された内部矛盾と現在値の集約が組合せによって欠落する。

2. **影響**: 拒否と終了コードは正しいため安全ゲートは維持されるが、E-DATA-04のmessageが要求する矛盾内容を全て提示せず、どのファイルを復旧すべきかの診断情報が不完全になる。

3. **根拠となる設計文書の規則ID**: `CLI-10`、`CLI-11`、`E-DATA-04`、`M1D-13`、`R4-02`。

4. **具体的な修正案**: lexicon・grammarのスキーマとmeta構造が型安全に参照できる場合は、最初のraise前に3ファイルの`data_version`相互比較も行い、schema/meta問題・内部矛盾・現在値不一致を同じ決定的message/detailへ集約する。3ファイルのうち1件だけ旧版、2件だけ旧版、meta内部不整合との併存を回帰検査する。
