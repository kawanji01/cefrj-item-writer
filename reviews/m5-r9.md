## 指摘

### R9-01 — minor — `scripts/finalize_set.py:448`

1. **問題**

   `main()` は stdin の JSON を構文解析した直後に `validate_set_dir()` を実行し、その後で `validate_metadata()` による FIN-01 内容検証と config snapshot 検証を行っている。このため複数の入力不正が同時に存在すると、仕様で定められた検証順序とは異なるエラーが先に返る。

   例えば、存在しない set directory と空 metadata を組み合わせると、次のコマンドは `E-INPUT-02` を返す。

   ```sh
   printf '{}\n' | .venv/bin/python scripts/finalize_set.py --set-dir output/20991231-235959-zzzz
   ```

   しかし CLI-21 の順序では、最初に stdin の形式・内容を検証するため、空 metadata は FIN-01 違反の `E-CONTRACT-01` として先に拒否される必要がある。

2. **根拠**

   `docs/architecture.md` の CLI-21 は、(1) stdin の parse と内容検証、(2) config snapshot の完全一致確認、(3) 既存 `set.json` の確認、の順を必須としている。現在は set directory の存在・配置確認が (1) の内容検証と (2) より前に割り込んでおり、規定されたエラー優先順位を満たしていない。

3. **修正案**

   set directory 名から `set_id` を副作用なく抽出する処理と、directory の存在・配置を確認する処理を分離する。そのうえで FIN-01 metadata の独立した内容検証を完了し、config snapshot を照合してから、set directory と既存 `set.json` の検証へ進む。CLI-21 の各段階に対応する関数呼出し順が `main()` から直接読める形にすると、今後の順序退行も防ぎやすい。
