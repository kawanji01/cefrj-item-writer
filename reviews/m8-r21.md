## R21-01 — major — `tests/unit/test_fixtures.py:1247` / `tests/unit/test_fixtures.py:1330` / `tests/unit/test_fixtures.py:2501`

1. **指摘内容**: CI-R-03のsensitive callable追跡は、callableを格納したコンテナを名前経由でアンパック・抽出する形と、ローカル関数がコンテナを返す形でfail-openになる。`target_bindings()`は代入右辺のASTが直接の`Tuple`/`List`でないアンパックを全て`None`へ落とし、`returned_sensitive_terminal()`は戻り値が`Call`/`IfExp`/`Subscript`のときしか間接追跡しない。実際に、次の4反例はいずれも`contract_dict_violations()`が違反ゼロを返したが、実行時には`unknown_helper()`由来の値を`write_json`へ渡す。

   ```python
   calls = [write_json]
   [fn] = calls
   fn(candidate_path, unknown_helper())

   calls = [write_json]
   fn = calls.pop()
   fn(candidate_path, unknown_helper())

   def choose():
       return (write_json,)
   choose()[0](candidate_path, unknown_helper())

   calls = {"sink": write_json}
   fn, = calls.values()
   fn(candidate_path, unknown_helper())
   ```

   既存のCI-R-03メタ回帰11件はpassするため、第4節fixtureでも製品直前段出力でもない入力をJSON書込みsinkへ到達させるこれらの経路をマージゲートが検出しない。

2. **根拠となる設計文書の規則ID**: `docs/testing-and-acceptance.md` CI-R-03・TST-08、`IMPLEMENTATION_PLAN.md` M8 DoD 1。

3. **具体的な修正案**: sensitive callableそのものだけでなく、callableを含むコンテナの要素identityを名前代入・アンパック・既知の抽出操作・ローカル関数の戻り値へ伝播する。静的に要素対応または抽出結果を確定できないコンテナ操作は、sensitive callableを保持し得る時点で`unresolved-sensitive`としてfail-closedにする。上記4形を自己負回帰へ追加し、正準fixture由来だけを通す同形の正常例も固定する。
